## 📘 Log Format Discrepancy & Resolution (System Integrity Lesson)

- **What caused the apparent log overwrite behavior?**
  - Prior audit log entries in `/cursor/auto-actions.log.md` were appended as standalone JSON code blocks. While technically correct for append operations, many Markdown renderers and agent viewers (including Cursor, VS Code, and GitHub) visually collapse or only display the last JSON block, creating the false impression that previous logs were overwritten.

- **What structural change was made?**
  - The audit log format was updated to wrap each entry in a structured Markdown block, including a section header, a fenced JSON code block, and a human-readable summary. This ensures each audit event is visually and semantically distinct, regardless of renderer.

- **What new format now ensures visual and semantic traceability?**
  - Each audit entry is now logged as:
    - A Markdown section header with folder and block context
    - A fenced JSON code block for machine parsing
    - A summary section for human/agent review
  - This format is append-safe, visually stackable, and diff-friendly, ensuring both human and agent trust in the audit trail.

- **Lesson for Codex protocol:**
  - Visual structure is as important as technical structure for trust in collaborative, zero-drift systems. All future audit logs will use this format to maintain clarity, traceability, and operational confidence.
