## 4. COMPREHENSIVE VERIFICATION SANITY CHECK

### Zero-Assumption Verification Methodology

Implement a rigorous verification methodology:

1. **Trust Nothing Without Evidence**:
   - Require direct file execution evidence for all functionality claims
   - Implement "verification at the source" approach for all components
   - Document negative findings alongside positive ones

2. **Complete Codebase Coverage Check**:
   - Run static analysis on the entire codebase to identify all components
   - Compare against claimed components in documentation
   - Create a "verification blind spot" report for any uncovered areas

3. **Functionality Verification Depth**:
   - For each component, verify:
     - Implementation existence (file verification)
     - Compilation/syntax correctness (build verification)
     - Basic functionality (unit test verification)
     - Integration capability (integration test verification)
     - Runtime behavior (execution verification)
     - Behavior under failure (resilience verification)

### Critical Component Verification Protocol

For each critical component:

1. **Deep Inspection**:
   - Line-by-line code review with documented findings
   - Test execution with validation of outputs
   - Interface verification against documented expectations
   - Error handling verification

2. **Truth-Based Assessment**:
   - Document actual state regardless of previous claims
   - Record verification evidence with timestamps and methods
   - Update all documentation to reflect verified reality

3. **Gap-Focused Reporting**:
   - Highlight gaps between claimed and actual functionality
   - Prioritize verification efforts based on criticality
   - Create a verification confidence score for each component
